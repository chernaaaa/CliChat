# План тестирования P2P чата

## 1. Подход
Базовую логику (парсер, UI) покрываем юнит-тестами, а взаимодействие клиента и сервера проверяем интеграционными тестами (JUnit 5).

## 2. План автотестов (Unit)
**Парсер аргументов (`CommandLineArgs`)**
- Запуск сервера (только `--username`).
- Запуск клиента (`--username`, `--peer`, `--port`).
- Ошибки: нет аргументов, нет порта, кривой порт.

**UI и логика (`ConsoleInterface`)**
- Форматирование строки: `[Время] Имя: Текст`.
- Системные сообщения.

## 3. Интеграционные тесты

**Базовое взаимодействие (`ChatIntegrationTest`):**
- ✅ **Client → Server:** Клиент отправляет сообщение, сервер получает с правильным именем и текстом.
- ✅ **Server → Client:** Сервер отправляет сообщение, клиент получает с правильным именем и текстом.
- ✅ **Bidirectional:** Многократный обмен сообщениями в обе стороны.

**Управление подключениями:**
- ✅ **Graceful disconnect:** Корректное отключение клиента, сервер получает уведомление.
- ✅ **Multiple connections rejection:** Попытка второго подключения отклоняется, первый клиент продолжает работу.

**Edge cases:**
- ✅ **Timestamp validation:** Проверка, что timestamp сообщения соответствует реальному времени.
- ✅ **Empty messages:** Пустые сообщения не отправляются.

## 5. Что НЕ тестировали

- Нагрузочное тестирование
- Тестирование в условиях нестабильной сети
- Reconnection после разрыва
- Шифрование сообщений
- История сообщений (persistence)
